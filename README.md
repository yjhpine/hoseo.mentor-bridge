# hoseo.mentor-bridge

> 멘토·멘티 매칭 플랫폼 제작

멘티가 단과대학별 멘토의 이력과 강의를 살펴보고, 원하는 멘토를 선택해 강의를 수강하고 1:1로 질문할 수 있는 웹 서비스입니다. 관리자는 멘토 페이지와 질의응답 현황을 관리하고, 질문·답변 내용을 확인해 강사료를 책정합니다.

이 문서는 초기 회의 내용을 정리한 요구사항이며, 구현 완료 여부를 나타내지는 않습니다.

## 참고 서비스

- [잇다 멘토 페이지](https://www.itdaa.net/mentors/427486)
- 멘토 소개와 탐색, 멘토링 서비스 구성을 참고합니다.

## 서비스 핵심 흐름

1. **회원가입**: 멘토와 멘티가 각 역할에 필요한 정보를 입력하고 가입합니다.
2. **멘토 페이지 개설**: 관리자가 단과대학별 구역을 생성하고, 멘토 페이지를 개설해 멘토를 등록합니다.
3. **이력·강의 등록**: 멘토가 본인 페이지에 이력과 강의를 등록합니다.
4. **멘토 탐색·선택**: 멘티가 여러 멘토를 둘러보고 원하는 멘토를 선택해 강의를 수강합니다.
5. **1:1 질문**: 멘티가 멘토와의 1:1 톡방에서 자유롭게 질문합니다.
6. **멘토 답변**: 멘토가 멘티의 질문에 **50자 이상**으로 답변합니다.
7. **운영 관리**: 관리자가 모든 질문·답변의 내용과 건수를 확인하고 강사료를 책정합니다.
8. **학기 단위 운영**: 학기별로 서비스를 운영하며, 멘토 만족도 조사를 진행합니다. 종료 시 멘티에게 한정되는 절차는 추가 확인이 필요합니다.

## 역할별 필요 기능

| 역할 | 필요 기능 |
| --- | --- |
| 관리자 | 단과대학별 구역 생성 및 해당 구역에 멘토 페이지 등록 |
| 관리자 | 멘토 페이지 개설 및 멘토 등록 |
| 관리자 | 전체 질의응답 내용 및 건수 확인 |
| 관리자 | 질문·답변을 확인한 후 강사료 책정 |
| 멘토 | 본인 페이지에 이력 및 강의 등록 |
| 멘토 | 멘티의 질문에 50자 이상 답변 |
| 멘티 | 멘토 목록 및 소개 페이지 탐색, 멘토 선택 |
| 멘티 | 멘토 강의 수강 |
| 멘티 | 1:1 톡방에서 멘토에게 질문 |

## 가입 시 필요한 정보

| 역할 | 필수 정보 |
| --- | --- |
| 멘토 | 기업명, 직무 분야, 이름 |
| 멘티 | 학과, 이름 |

로그인 수단과 계정 식별 방식은 추후 결정합니다.

## 멘토 페이지 구성 예시

단과대학별 구역 아래에 멘토 페이지를 배치합니다. 아래 명칭은 예시입니다.

| 구역 | 멘토 예시 |
| --- | --- |
| 공과대학 | OO전자 소속 OOO 멘토 |
| 자연과학대학 | OO식품 소속 OOO 멘토 |
| 인문대학 | OO회사 소속 OOO 멘토 |

각 멘토 페이지에는 기업명, 직무 분야, 이름, 이력, 등록한 강의를 제공합니다.

## 학기 운영 및 만족도 조사

- 서비스는 **학기 단위**로 운영합니다.
- **멘토 만족도 조사**를 진행합니다.
- 회의 메모의 “학기별 운영 후 종료 시 멘티 한정”은 적용 절차가 명시되지 않았습니다. 학기 종료 후 만족도 조사에 멘티만 참여한다는 의미인지 확인이 필요합니다.

## 기술 및 데이터 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 웹 서비스 | 관리자·멘토·멘티 역할별 기능과 접근 권한 제공 |
| 데이터베이스 | 사용자 정보, 단과대학 구역, 멘토 이력·강의, 질의응답 내용 저장 |
| 1:1 톡방 | 멘토와 멘티 간 질문·답변 및 대화 이력 조회 지원 |
| 답변 길이 검증 | 멘토 답변이 50자 이상인지 확인 |
| 운영 현황 조회 | 관리자가 전체 질의응답 내용과 건수를 확인할 수 있도록 지원 |
| 사용자 PC 기억 | 재방문 시 사용자를 기억하는 기능이 필요하며, 로그인 유지 등 구체적인 동작은 추후 결정 |

사용자 PC 기억 기능은 데이터베이스만으로 구현 범위가 정해지지 않으므로, 로그인·세션 처리와 브라우저의 쿠키 또는 저장소 사용 방식을 함께 검토합니다. 선택한 기술 스택은 [기술 스택](#기술-스택)에 정리했습니다.

## 개발 환경

1. Node.js 20 이상을 설치합니다.
2. 의존성을 설치합니다: `npm install`
3. `.env.example`을 `.env.local`로 복사하고 Supabase 프로젝트의 URL과 publishable key를 넣습니다.
4. 개발 서버를 실행합니다: `npm run dev` → http://localhost:3000
5. (선택) 레퍼런스 레포를 받습니다: `npm run refs`

DB 스키마는 `supabase/migrations/`의 SQL 파일로 관리합니다. 새 파일은 `npx supabase migration new <이름>`으로 만듭니다.

## 추가 확인 사항

- **학기 종료 절차**: “멘티 한정”이 적용되는 기능과 만족도 조사 대상·시점
- **강의 제공 방식**: 영상, 자료, 실시간 강의 등 수강 형태
- **강사료 책정 기준**: 질의응답 건수와 내용의 반영 방식
- **답변 글자 수 기준**: 50자 계산 시 공백 포함 여부
- **사용자 PC 기억 범위**: 로그인 유지 여부와 유지 기간
