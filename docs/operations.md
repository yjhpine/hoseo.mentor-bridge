# 운영 안내

호서대학교 멘토링 서비스를 운영하는 관리자를 위한 안내입니다. 개발 내용은 [architecture.md](architecture.md), 백업은 [backup.md](backup.md)에 있습니다.

- 사이트 주소: <https://hoseo-mentor-bridge.yjhpine123.workers.dev>
- 관리자 로그인: 소속 **관리자** + 이름 + PIN
- 개인정보 보호책임자: 호서대학교 창업팀 양정환 (010-3830-5972)

## 처음 한 번 할 일

1. **관리자 PIN 바꾸기**: 오른쪽 위 내 이름 → PIN 변경. 처음 만든 임시 PIN은 꼭 바꿉니다.
2. **관리자 더 만들기 (권장)**: 관리자 → 사용자 → 관리자 계정 만들기. 관리자가 한 명뿐이면 그 사람이 PIN을 잊었을 때 아무도 초기화해 줄 수 없습니다.
3. **구역·학과 확인**: 관리자 → 구역·학과. 단과대학 구역과 학과가 맞는지 보고, 필요하면 추가하거나 숨깁니다. 숨긴 학과는 가입 화면에 나오지 않습니다.
4. **직무 분야 확인**: 관리자 → 직무 분야. 멘토가 가입할 때 고르는 목록입니다.

## 한 학기 운영 순서

| 순서 | 할 일 | 화면 |
| --- | --- | --- |
| 1 | 학기를 만들고 **현재 학기로 지정** | 관리자 → 학기 |
| 2 | 멘토에게 사이트 주소를 보내 가입을 받음 (소속 "멘토" 선택) | — |
| 3 | 가입한 멘토를 단과대학 구역에 배치하고 **개설** | 관리자 → 멘토 개설 |
| 4 | 멘토가 자기 페이지에 소개·경력·강의를 올림 (자료 파일은 개설된 뒤에 올릴 수 있음) | 멘토: 내 멘토 페이지 |
| 5 | 재학생에게 사이트 주소를 알림 (소속은 자기 학과) | — |
| 6 | 학기 중 질의응답 현황을 가끔 확인 | 관리자 → 질의응답 |
| 7 | 학기가 끝나면 **학기 종료** (만족도 조사 마감일을 정함, 기본 2주 뒤) | 관리자 → 학기 |
| 8 | 조사 마감 뒤 만족도 결과 확인 | 관리자 → 만족도 |
| 9 | 학기 **단가**(답변 1건당, 상한 선택)를 정하고, 멘토별 계산 금액을 확인해 **강사료 책정**, 지급한 뒤 **지급 완료** 표시 ([강사료 책정과 지급](#강사료-책정과-지급)) | 관리자 → 강사료 |
| 10 | 지급을 마친 뒤 **전체 백업** 받기 | 관리자 → 백업 |
| 11 | 다음 학기를 만들고 현재 학기로 지정 | 관리자 → 학기 |

알아 둘 점

- 현재 학기가 없거나 종료된 상태면 멘티가 새 톡방을 열 수 없습니다. 학기를 종료한 뒤 다음 학기를 지정하기 전까지는 새 질문을 시작할 수 없습니다.
- 학기를 종료하면 그 학기 톡방은 읽기 전용이 됩니다. 되돌릴 수 없으니 확인 창을 잘 읽고 누릅니다.
- 만족도 조사는 그 학기에 그 멘토에게 질문하고 답변을 받은 멘티만, 멘토마다 한 번 응답합니다. 멘티는 홈 안내와 마이페이지에서 응답합니다. 관리자 화면에는 응답자 이름이 나오지 않습니다.
- 강사료는 학기 단가로 계산 금액을 추천받아 관리자가 확정하고, 지급한 뒤 지급 완료로 표시합니다. 자세한 순서는 아래 [강사료 책정과 지급](#강사료-책정과-지급)에 있습니다.

## 멘토 개설

관리자 → 멘토 개설에는 가입한 멘토가 상태별로 모입니다.

| 상태 | 뜻 | 할 수 있는 일 |
| --- | --- | --- |
| 개설 대기 | 가입만 한 멘토. 멘티에게 보이지 않음 | 구역을 골라 **개설**, 또는 **보류** |
| 공개 | 멘티가 목록에서 보고 질문할 수 있음 | **구역 변경**, **비공개** |
| 비공개 | 보류했거나 내린 멘토. 멘티에게 보이지 않음 | **다시 공개** |

기업명·직무 분야를 잘못 썼으면 같은 화면의 "기업명·직무 분야 고치기"에서 고칩니다.

**프로필 사진**: 멘토가 내 멘토 페이지의 "프로필 사진"에서 직접 올리고 바꾸거나 지웁니다. JPG·PNG·WEBP 사진을 고르면 가운데를 정사각형으로 잘라 작게 줄여 올리고, 올리면 바로 멘토 목록·상세에 보입니다. 사진은 로그인한 사람만 볼 수 있습니다. 부적절한 사진은 관리자가 멘토 개설 화면에서 멘토 옆 **사진 지우기**로 지웁니다(기본 이미지로 돌아감). 탈퇴 처리하면 사진도 함께 지워집니다.

멘토가 강의 자료로 올릴 수 있는 파일은 PDF, 한글(HWP·HWPX), 워드, 엑셀, 파워포인트, 이미지(PNG·JPG), ZIP, TXT이고 20MB까지입니다. 영상은 유튜브 등 외부 링크로 등록하게 안내합니다.

## 강사료 책정과 지급

관리자 → 강사료에서 학기마다 합니다. 금액은 사이트가 계산해 추천하고, 최종 금액은 관리자가 정합니다 (설계 11장 3·26·29~31번).

1. **학기 고르기**: 위쪽에서 학기를 고릅니다. 진행 중인 학기는 건수가 더 늘 수 있으니 보통 **학기를 종료한 뒤** 책정합니다.
2. **이 학기 단가 저장**: "답변 1건당 단가"와 "멘토 1명 상한"을 원 단위로 넣고 **단가 저장**을 누릅니다.
   - 상한은 비워 두면 상한이 없습니다.
   - 단가는 학기마다 따로 저장됩니다. 다음 학기에 단가를 바꿔도 지난 학기 기준은 그대로 남습니다.
   - 단가와 강사료는 관리자만 볼 수 있고 멘토에게는 보이지 않습니다.
3. **계산 금액 확인**: 멘토마다 톡방·질문·답변 수와 `계산 금액: 답변 7건 × 10,000원 → 상한 50,000원 적용 = 50,000원`처럼 나옵니다. 계산 금액이 금액 칸에 미리 채워집니다.
4. **책정**: 금액을 확인하고(필요하면 고쳐서) 메모를 남긴 뒤 **책정**을 누릅니다.
   - 책정할 때의 질문·답변 수, 단가, 책정한 관리자와 시각이 함께 저장됩니다.
   - 계산 금액과 다르게 책정하면 "계산 금액과 다르게 책정함"이 표시됩니다.
   - 책정 뒤 건수가 바뀌면(메시지를 숨긴 경우 등) "책정 뒤 건수가 바뀌었습니다"가 나옵니다. 확인하고 **다시 책정**합니다.
5. **지급 완료 표시**: 실제로 지급한 뒤 **지급 완료**를 누르고 확인 창에서 확인합니다.
   - 지급 시각과 처리한 관리자가 기록되고, 금액·메모 칸이 잠깁니다.
   - 잘못 눌렀거나 금액을 고쳐야 하면 **지급 취소**를 누른 뒤 다시 책정합니다.
6. **합계 확인**: 화면 위에 책정, 지급 완료, 미지급 인원과 합계 금액이 나옵니다. 미지급이 0명이면 그 학기 지급이 끝난 것입니다.

건수 세는 법

- **질문 1건**: 멘티가 연달아 보낸 메시지 묶음 하나
- **답변 1건**: 질문 뒤에 멘토가 연달아 보낸 메시지 묶음 하나. 여러 번 나눠 보내도 1건이고, 질문 없이 멘토가 먼저 보낸 메시지는 세지 않습니다.
- 관리자가 숨긴 메시지는 세지 않습니다. 멘토 답변은 공백을 뺀 50자 이상이어야 보낼 수 있습니다.

학기 강사료 기록은 **전체 백업**(관리자 → 백업)에 단가와 함께 들어갑니다. 지급을 마치면 백업을 받아 두세요.

## 사용자 요청 처리

| 요청 | 처리 |
| --- | --- |
| PIN을 잊었어요 | 관리자 → 사용자 → 그 사람의 **PIN 초기화**. 화면에 한 번만 보이는 임시 PIN을 본인에게 전합니다. 다음 로그인 때 새 PIN으로 바꾸게 됩니다. 메일이 없어서 스스로 찾을 수는 없습니다. |
| 이름이나 학과를 잘못 가입했어요 | 관리자 → 사용자 → **이름·소속 바꾸기**. 바꾼 이름·학과로 로그인하게 됩니다. 멘토·관리자는 소속이 바뀌지 않습니다. |
| 같은 이름이 있다고 가입이 안 돼요 | 가입 화면이 구분 문자(영문·숫자 1~3자)를 붙이라고 안내합니다. 예: 홍길동A. 로그인할 때도 이름칸에 붙여 씁니다. |
| 탈퇴하고 싶어요 | 본인 확인 뒤 백업을 받고, 관리자 → 사용자 → **탈퇴 처리** (이름을 입력해 확인). 그 사람의 질문·답변, 강의, 수강·만족도 기록이 모두 지워지고 되돌릴 수 없습니다. 화면에는 본인 탈퇴 기능이 없습니다. |
| 내 정보를 보여 주세요 / 고쳐 주세요 | 개인정보 열람·정정 요청입니다. 백업 CSV에서 그 사람의 기록을 찾아 전하거나, 위 방법으로 고칩니다. 지체 없이 처리합니다. |
| 로그인이 안 돼요 | 소속·이름(구분 문자 포함)·PIN을 다시 확인하게 합니다. 자동 입력 방지 위젯이 "성공"이 된 뒤에 버튼을 누르는지 확인합니다. 그래도 안 되면 PIN 초기화. |

## 정기적으로 할 일

| 언제 | 할 일 |
| --- | --- |
| 학기마다 | 전체 백업 ([backup.md](backup.md)), 보관 기간이 지난 회원 정리 (관리자 → 백업 아래쪽 목록) |
| 백업 파일이 1년 지나면 | 그 파일 삭제 |
| 처리방침을 바꿀 때 | 바뀐 내용을 시행 7일 전에 알림. 개발 담당자가 `lib/privacy/policy.ts`의 시행일을 올림 |

## 자동으로 돌아가는 것

- **Supabase 일시 정지 방지**: 무료 플랜은 7일 동안 사용이 적으면 데이터베이스가 정지됩니다. 매일 한국 시각 12:17에 Cloudflare가 데이터베이스를 한 번 읽어 정지를 막습니다.
- **자동 가입·로그인 방지**: 가입·로그인 화면의 Cloudflare Turnstile 위젯이 사람인지 확인합니다.
- **배포**: GitHub `main`에 병합하면 Cloudflare가 1~2분 안에 사이트를 새로 배포합니다.

## 문제가 생겼을 때

| 증상 | 볼 곳 |
| --- | --- |
| 사이트가 전혀 열리지 않음 | Cloudflare 대시보드 → Workers → `hoseo-mentor-bridge` → 배포 기록과 Logs |
| 로그인·화면은 열리는데 데이터가 안 나옴, "프로젝트가 정지됨" 메일 | Supabase 대시보드에서 `hoseo-mentoring` 프로젝트를 복구(Restore). 정지 뒤 90일 안에 해야 합니다. Cloudflare → Workers → `hoseo-mentor-bridge` → Settings → Trigger events에서 매일 실행이 실패하고 있지 않은지도 봅니다 |
| 가입·로그인에서 "자동 입력 방지 확인에 실패" | 페이지를 새로 고친 뒤 다시 시도. 계속되면 Supabase → Authentication → Bot and Abuse Protection의 Turnstile secret key와 Cloudflare Turnstile 위젯의 호스트 이름을 확인 |
| 여러 사람이 한꺼번에 로그인할 때 "요청이 너무 많습니다" | 학교 Wi-Fi는 여러 사람이 같은 IP를 써서 잠깐 제한될 수 있습니다. 몇 초 뒤 다시 하면 됩니다 |
| 데이터를 잘못 지웠음 | [backup.md](backup.md)의 "되살리기". 개발 담당자에게 요청 |

## 계정과 비밀 정보

- Supabase secret 키와 Turnstile secret key는 각 대시보드에만 있고, 저장소나 메신저에 올리지 않습니다.
- 관리자 PIN은 개인마다 따로 쓰고 공유하지 않습니다. 관리자가 바뀌면 새 관리자 계정을 만들고, 그만둔 관리자 계정은 다른 관리자가 탈퇴 처리합니다.
