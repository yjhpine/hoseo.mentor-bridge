# 백업 절차

Supabase 무료 플랜은 자동 백업을 내려받을 수 없습니다. 그래서 관리자가 관리자 화면에서 직접 백업 파일을 받아 보관합니다. 설계 배경은 [architecture.md](architecture.md) 6.7과 11장 21번에 있습니다.

## 언제 받나

| 때 | 이유 |
| --- | --- |
| 학기를 종료한 뒤 (만족도 조사 기간이 끝난 뒤) | 한 학기의 질의응답·강사료·만족도 기록을 남김 |
| 회원을 탈퇴 처리하기 전 | 탈퇴하면 그 회원의 데이터가 되돌릴 수 없게 지워짐 |
| 학과·구역 정리처럼 데이터를 크게 바꾸기 전 | 실수했을 때 되돌릴 근거 |
| 방학 시작 전 | 매일 정기 실행으로 일시 정지를 막지만, 만일을 대비해 받아 둠 (10장) |

## 받는 방법

1. 관리자 계정으로 로그인합니다.
2. 관리자 메뉴 → **백업** (`/admin/backup`) → **전체 백업 받기 (JSON)** 을 누릅니다.
3. `hoseo-mentor-backup-날짜-시각.json` 파일이 내려받아집니다.
4. 엑셀로 볼 표가 필요하면 같은 화면에서 표마다 **CSV** 버튼을 누릅니다. CSV는 보기용이고, 되살릴 때는 JSON을 씁니다.

## 들어 있는 것과 없는 것

| 들어 있음 | 없음 |
| --- | --- |
| 설정, 단과대학·학과·직무 분야, 회원(이름·소속·역할), 멘티·멘토 프로필, 개인정보 동의 기록, 학기, 톡방·메시지·읽음 표시, 강의·차시·수강 신청, 강사료 단가·강사료(지급 여부 포함), 만족도 응답, 멘토 사진 경로, 로그인 계정의 가상 이메일·가입 시각·마지막 로그인 시각 | PIN(해시도 넣지 않음), 강의 자료 파일(Storage `course-files`), 멘토 프로필 사진 파일(Storage `avatars`), 관리자 생성용 임시 허가(`admin_invites`) |

- 강의 자료 파일과 프로필 사진은 멘토가 원본을 갖고 있으므로 백업하지 않습니다. 파일도 보관해야 하면 Supabase 대시보드 → Storage → `course-files`·`avatars`에서 내려받습니다.
- PIN이 없으므로 백업으로 되살린 계정은 관리자가 임시 PIN을 새로 정해 줘야 로그인할 수 있습니다.

## 보관

- 백업 파일에는 이름, 소속, 질문·답변 내용이 들어 있습니다. 개인정보 처리방침(`/privacy`)에 적은 대로 다룹니다.
- 암호를 건 저장 장치(암호를 건 USB, 접근 권한을 정한 학교 공유 드라이브 등)에 둡니다. 개인 메신저나 메일로 보내지 않습니다.
- 파일 이름의 날짜로부터 **1년**이 지나면 지웁니다. 휴지통도 비웁니다.
- 누가 언제 받았는지 간단히 적어 둡니다 (예: 학기 운영 문서에 "2027-01-05 양정환, 2026-2학기 종료 백업").

## 보관 기간이 지난 회원 정리

1. `/admin/backup`의 **보관 기간이 지난 회원**에서 마지막 이용 후 1년이 지난 멘티·멘토를 확인합니다.
2. 먼저 전체 백업을 받습니다.
3. 회원마다 **탈퇴 처리**를 누르고 이름을 입력해 지웁니다.

학기마다 백업을 받을 때 함께 확인하면 됩니다.

## 되살리기

화면에서 되살리는 기능은 없습니다. 데이터가 망가졌을 때만 개발 담당자가 처리합니다.

1. 지금 상태를 먼저 백업합니다.
2. 백업 JSON의 `tables`에서 필요한 표와 행을 골라, Supabase 대시보드의 SQL Editor나 스크립트로 다시 넣습니다. `profiles`를 넣으려면 같은 `id`의 로그인 계정이 먼저 있어야 하므로, 계정은 `admin-users`(관리자 API)로 같은 가상 이메일로 다시 만든 뒤 임시 PIN을 정해 줍니다.
3. 표 사이의 연결(외래 키) 때문에 넣는 순서가 중요합니다: 설정·구역·학과·직무 분야 → 회원·멘티·멘토 → 학기 → 톡방 → 메시지 → 강의 → 차시 → 수강 → 강사료·만족도.
4. 다 넣은 뒤 Supabase 보안 점검(advisors)을 돌리고 화면에서 확인합니다.
